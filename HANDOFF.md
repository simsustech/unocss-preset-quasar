## What's in place

1. **Parity fixture** (`test/fixtures/reference-selectors.json`) — 163 dark-scoped selectors extracted from the deployed reference CSS. Generated by `scripts/extract-reference-fixture.mjs`. Idempotent (no timestamp).

2. **Coverage test** (`test/_parity-snapshot.test.ts`) — generates CSS with the full safelist, checks fixture coverage. Currently **162/162 (100%)** of the selectors the preset can control. Report written to `test/parity-report.txt`.

3. **Dark yield pattern** — inline `symbols.selector` yields in existing generators:

   ```ts
   yield {
     [symbols.selector]: (sel) => `.body--dark ${sel}`,
     color: 'var(--q-primary)'
   }
   ```

   Always interpolate `${sel}` rather than hardcoding the selector: a hardcoded
   string silently stops tracking the token if the rule is ever re-keyed.

4. **New components** — `src/components/notification/`, `src/components/message/`, `src/components/loading/` with rules + dark yields. Registered in barrel + safelist.

## Root cause (solved)

`delegateMatchers` in `src/rules/merge.ts` detected scoped yields with:

```ts
Object.getOwnPropertySymbols(item).length === 0
```

But UnoCSS's control keys are **plain strings**, not JS symbols (`symbols.selector
=== '$$symbol-selector'`), so that check was always true. Every scoped yield was
classified as a plain declaration object and folded into the util's own object via
`Object.assign` — which copies the control key too. The result was a single rule
carrying only the LAST matcher's selector with every other matcher's properties
underneath it, and no `.body--dark` rule at all.

That is why the symptom looked random: only components whose regex appeared
**once** in the preset survived, because `delegateMatchers` never ran for them.
btn-group had five duplicate `/^q-btn-group$/` matchers, so it lost its dark rule;
field/editor/toggle kept theirs only because their scoped yield happened to be the
last matcher of the group.

Fixed by looking the control keys up by name (`CONTROL_KEYS`). Pinned by two tests
in `test/no-duplicate-rules.test.ts`, both verified to fail against the old
detection.

### Known latent risks

- `symbols.selector` yields that hardcode their selector instead of using `${sel}`
  still exist across several components (e.g. `.q-table tbody td:before`,
  `.q-checkbox--dark .q-checkbox__inner:before`, the `q-editor__btn*` rules). They
  produce correct output today, but re-keying the rule silently breaks them.
- UnoCSS merges rules with identical declaration bodies into one comma-joined
  selector list, so a utility can share a block with an unrelated component rule.
  Order is preserved by first occurrence; assert order with a selector-list-aware
  lookup, not a standalone `.sel{` search.
- **toggle truthy** (5) — inner--truthy thumb/track/thumb:after.
- **btn-group** (4) — `.q-btn-group > .q-btn-item`, `.q-btn-group > .q-btn`, `.q-btn-group > .q-btn-group:first-child > .q-btn--active`.
- **checkbox** (4) — inner--indet/truthy, dark variants.
- **editor** (4) — toolbar border, content hr, toolbar-group divider.
