# Quasar Components

- Quasar sets inline width styles on components when `dense=true` (e.g., QToggle gets a hardcoded inline `width`). Override these with CSS (`!important` or higher-specificity selectors) in the preset styles rather than letting Quasar's inline width break the layout. Confidence: 0.70
- Quasar uses extensive outdated custom flexbox patterns (row/col classes); do not copy these. Use modern CSS strategies (Tailwind-style utility classes, CSS Grid, modern flexbox) to achieve the same visual look. Confidence: 0.85
- When defining wrapper props/defaults for Quasar components (QSliderProps, QBtnProps, etc.), always cross-check against Quasar's actual prop schema (node_modules sources) — do not guess types like `''` for boolean-only props, since coercions to `undefined` can break library internals (e.g. `Object.keys(undefined)`). Confidence: 0.80
- For two-way binding components (QDialog, QMenu, etc.), do NOT pass model-value via `v-bind="boundProps"` — it breaks two-way reactivity. Instead, use boundProps.modelValue as the initial default for a local `ref`, then bind with `v-model`. Alternatively, ensure boundProps is reactive (computed with get/set) so the component can update it. Confidence: 0.85
- When the route manifest component name differs from the underlying Quasar component name (e.g. route `QChat` vs Quasar `QChatMessage`), use the route manifest name for page-level naming (Vue files, schema constants, defaults objects) — not the Quasar internal name. Confidence: 0.65
- When fixing/setting default values for Quasar component props files, set defaults for required props first before handling optional ones. Confidence: 0.70
- Per-component preview pages (e.g. QTreePage, QListPage, QSelectPage) must pass realistic default dummy data to the component in the template — e.g. QTree needs sample `nodes`, QList needs sample items, QSelect needs sample `options`. Otherwise screenshots/visual regressions show only the empty-state label ("No nodes available", "No options") and the component is effectively untested. Confidence: 0.90
- Quasar's runtime tag names drop the kebab for some multi-word components: `q-ajaxbar` (not `q-ajax-bar`), `q-virtualscroll` (not `q-virtual-scroll`), `q-popupedit` (not `q-popup-edit`). Use these unhyphenated names in CSS selectors / Playwright locators. Confidence: 0.85
- When placing Quasar form components (QInput, QToggle, QCheckbox, QSelect) as direct children of `row`/`col-*` grid cells, the flexbox layout causes vertical misalignment because components have different inherent heights. Wrap each in a container with consistent alignment or use QForm with proper spacing instead of raw grid cells. Confidence: 0.80
- In Playwright tests, use ARIA-role selectors (`getByRole('switch')`, `getByRole('checkbox')`) for Quasar toggle/checkbox components instead of native `input[type="checkbox"]` selectors. Quasar's hidden native inputs (`class="hidden q-toggle__native..."`) don't always sync their `checked` property — the ARIA role reflects the actual visual state. Confidence: 0.75
- When QToggle looks visually broken in Control Panel / form layouts (especially with `dense`), fix the underlying CSS/flexbox issue in the preset styles rather than removing the `dense` prop or restructuring the parent layout. The user prefers dense toggles to actually work correctly in all contexts. Confidence: 0.80
- When making CSS/styling changes to a component, visually screenshot all prop variations (e.g. dense, left-label, disabled, checked) — not just the default state. Prop-level visual regressions like dense toggle sizing are caught by checking variations, not by a single default screenshot. Confidence: 0.80
