# Preset Styling

- quasar.css in the unocss-preset-quasar package is custom MD2 code — do NOT use it as a reference or baseline for any component styling, MD3 or otherwise. The new preset uses modern flexbox and CSS; quasar.css patterns are outdated and should not be consulted when debugging or designing styles. MD3 styles should derive from the MD3 spec (material_design_3_machine_spec.json) and independent design judgment, not from quasar.css values. Confidence: 0.90
- Use MD3 design-token CSS custom properties (e.g., `var(--md3-on-surface)`, `var(--md3-surface-container)`, `var(--md3-outline-variant)`) for component color/background/border values instead of hardcoded hex values like `#000` or `#fff`. Token-based colors auto-flip correctly between light and dark modes and stay consistent with the MD3 spec. Confidence: 0.70
- Keep CSS/shortcuts as simple as possible — avoid unnecessary complexity, extra wrappers, or over-engineering. Prefer the minimal set of rules that achieves the correct visual result. Confidence: 0.85
- Do not use `position: absolute` or similar positioning hacks in preset shortcuts unless absolutely unavoidable. Prefer modern layout approaches (flexbox, grid, margin-auto centering) to position elements. Confidence: 0.85
- Use state-of-the-art CSS techniques — no legacy or outdated approaches. Prefer modern flexbox, CSS grid, logical properties, and contemporary best practices. The preset targets modern browsers; old-IE compatibility patterns have no place here. Confidence: 0.85
- MD2 and MD3 are separate styling systems with different specs. Do not backport MD3 changes to MD2 just for consistency — changes to each system should be driven by their own respective spec/requirements. MD2 is based on quasar.css, MD3 is based on material_design_3_machine_spec.json. Confidence: 0.70
- Both MD2 and MD3 styles must visually match their respective official specifications (m2.material.io / m3.material.io); the final output must be fully working and tested against each spec, not just "different from each other". Confidence: 0.90
- Visual regression baselines must cover ALL components, not just a representative subset (e.g. QBtn). Every component needs its own screenshot baseline per style. Confidence: 0.85
- The canonical MD2/MD3 spec for this project lives in machine-readable JSON files named `material_design_2_machine_spec.json` and `material_design_3_machine_spec.json` (locally, in the project) — use these as the authoritative spec source for audits, not just the m2/m3.material.io websites. Confidence: 0.85
- Generate one screenshot per distinct use case/variant of every component (not just one "default" per component). Use descriptive filenames so each variant is easy to locate/inspect. Edge/empty states (e.g. `nodes: []` for QTree) are valid states and must be tested as their own use case, not omitted. Confidence: 0.80
- In UnoCSS shortcut strings, `_` (single underscore) is treated as a space combinator — Quasar BEM class names like `q-field__label` must have their `__` escaped to `\\_\\_` using the `qe()` helper from `_helpers.ts`, otherwise the generated CSS selectors will never match the DOM. When CSS rules appear to not take effect, check `__uno.css` output (via `curl localhost:PORT/__uno.css`) for broken selectors like `q-field _label` (space instead of `__`). Confidence: 0.85
